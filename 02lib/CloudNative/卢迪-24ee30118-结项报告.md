- 遇到的问题及解决方案：
	- 问题1：初期在本地机器部署 RocketMQ 和 EventBridge 时，出现 RocketMQ broker 部署失败的问题
		- 解决方案：检查了输出日志和启动的 bash 文件，发现是机器内存不满足 jvm 需要的内存导致启动失败。通过在阿里云服务器上部署解决
		
	- 问题2：初期通过 Postman 测试 SDK API 时，请求返回体正常。但是在测试生成的 java 版本代码时，发现请求返回体的各参数提取结果为空，且 statusCode 是 200。
		- 解决方案：通过抓包确认 Postman 和 测试代码发出的请求是一致的，排除请求问题。在排查请求返回体解析部分的代码时，发现虽然 EventBridge 源代码中，通过 @SerializedName 标注的请求体参数为首字母大写，但是实际请求体中的参数仍为小写开头。而解析参数时是用首字母大写的变量名，因而导致解析结果为空。通过修改解析参数名解决。
		
	- 问题3：实现 dara 版本 SDK 时，发现 rpc 传输的部分 request 和 response 中包含了 darabonba 目前尚未支持的 Date 和 Enum
		- 解决方案：和导师讨论后决定采用 String 类型作为替代，测试效果达到预期。
		
	- 问题4：测试 事件类型API 时，报错 500 Internal Server Error。
		- 解决方案：排查 EventBridge 日志后发现是 EventBridge 内部 SQL 语法问题，联系项目导师修复解决。
		
	- 问题5：测试 php 和 csharp 版本 demo 时，出现生成或运行时错误
		- 解决方案：通过咨询 darabonba 维护同学解决。
