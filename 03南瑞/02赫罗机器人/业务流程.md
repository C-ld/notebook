## 系统业务总览

系统围绕**安全生产/工作票管理**场景设计，共包含 **一个后台自动业务 + 六个主动触发场景**。

---

### 一、大厅迎宾（后台自动运行）

由 `LobbyWatcher` 驱动，无需用户触发，持续后台运行：

```
摄像头轮询(每2秒) → 人脸检测 → 匹配工票人员库 → 问候 + 推送签到提示
```

1. 摄像头持续抓帧做人脸检测
2. 连续命中 N 次（默认 2 次）确认身份
3. 查询该人员在工作票中的角色（工作负责人 / 成员）
4. TTS 播报个性化问候（如"周易，你好"），同时胸屏展示签到提示
5. ***含冷却机制：同一人 5 分钟内不重复问候（未生效？）***

---

### 二、六个业务场景（语音/指令触发）

用户通过语音指令启动（如"工作负责人签到"、"安全交底"等），或 Hermes Agent 根据对话意图启动。

#### 通用执行模型

所有场景共享同一个执行框架：

```
前置条件检查 → 解析参与人员 → TTS播报引导 → 人脸识别 → 结果上报
```

---

#### 1. 工作负责人签到 (`workLeaderSignIn`)

| 项目       | 说明                                                          |
| -------- | ----------------------------------------------------------- |
| **触发词**  | "工作负责人签到"、"负责人签到"、"签到"                                      |
| **参与人员** | 仅工作负责人                                                      |
| **识别模式** | `SINGLE_RETRY` — 单人识别，最多重试 3 次                              |
| **流程**   | ① TTS 引导"请工作负责人正对摄像头" → ② 人脸识别 → ③ **成功**：标记签到完成 → ④ 上报安全记录 |

---

#### 2. 安全交底 (`AQJD`)

| 项目       | 说明                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| **触发词**  | "安全交底"、"开始交底"、"进行交底"                                                                                         |
| **参与人员** | 工作负责人 + 全部交底成员                                                                                               |
| **识别模式** | `MULTI_MEETING` — 多人会议识别，要求全部人员到场                                                                            |
| **流程**   | ① TTS 引导"请所有交底人员站到摄像头前方" → ② 多人人脸识别（必须所有人到场） → ③ **成功**：播报"请工作负责人 XXX 进行安全交底" → ④ 录音转写交底发言 → ⑤ 上报安全记录 + 录音文件 |

---

#### 3. 开工会 (`KGH`)

| 项目 | 说明 |
|------|------|
| **触发词** | "开工会"、"开始开会" |
| **参与人员** | 工作负责人 + 全部成员 |
| **识别模式** | `MULTI_MEETING` |
| **流程** | ① 多人识别 → ② 工作负责人发言 → ③ 录音转写 → ④ 上报（类型标记 `inoutType: 开工会`） |

---

#### 4. 收工会 (`SGH`)

| 项目 | 说明 |
|------|------|
| **触发词** | "收工会"、"收工开会" |
| **参与人员** | 工作负责人 + 全部成员 |
| **识别模式** | `MULTI_MEETING` |
| **前置条件** | `check_work_status_sgh`（需有进行中的工作状态才可收工） |
| **流程** | 与开工会一致，上报 `inoutType: 收工会` |

---

#### 5. 人员进场 (`workerEnter`)

| 项目 | 说明 |
|------|------|
| **触发词** | "人员进场"、"开始进场"、"进场" |
| **参与人员** | 尚未进场的人员（`NOT_ONSITE`） |
| **识别模式** | `MULTI_IO` — 多人进出识别，不要求全员 |
| **前置条件** | ① 时间窗口校验 ② 工作状态校验 ③ 有待进场人员 |
| **流程** | ① 人脸识别进场人员 → ② **成功**：将识别到的人员加入"在场人员集合" → ③ 上报进场记录 |

---

#### 6. 人员出场 (`workerExit`)

| 项目 | 说明 |
|------|------|
| **触发词** | "人员出场"、"开始出场"、"出场" |
| **参与人员** | 已在场的人员（`ONSITE_ONLY`） |
| **识别模式** | `MULTI_IO` |
| **前置条件** | 有待出场人员 |
| **流程** | ① 人脸识别出场人员 → ② **成功**：从"在场人员集合"移除 → ③ 上报出场记录 |

---

### 三、场景控制指令

所有场景运行期间支持以下控制词（不需要经过 Hermes，本地直接处理）：

| 指令 | 效果 |
|------|------|
| **"继续"** | 推进当前场景（如跳到下一步） |
| **"结束"** | 结束当前场景/发言 |
| **"取消"** | 取消当前全部场景 |

---

### 四、整体业务状态流转

```
         ┌──────────────┐
         │  大厅迎宾     │ ← 后台持续运行（摄像头 → 人脸 → 问候 → 签到提示）
         │  (自动)      │
         └──────┬───────┘
                │ 用户说"签到"
                ▼
  ┌─────────────────────────────┐
  │   工作负责人签到              │
  │   (单人识别 → 签到确认)       │
  └─────────────┬───────────────┘
                │ 签到完成
                ▼
  ┌─────────────────────────────┐
  │   安全交底 / 开工会           │
  │   (多人识别 → 发言 → 录音)    │
  └─────────────┬───────────────┘
                │
                ▼
  ┌─────────────────────────────┐
  │   人员进场                   │
  │   (识别 → 加入在场集合)       │
  └─────────────┬───────────────┘
                │ 工作执行中...
                ▼
  ┌─────────────────────────────┐
  │   人员出场                   │
  │   (识别 → 移出在场集合)       │
  └─────────────┬───────────────┘
                │
                ▼
  ┌─────────────────────────────┐
  │   收工会                     │
  │   (多人识别 → 发言 → 完结)    │
  └─────────────────────────────┘
```

**关键约束**：
- 同一时间只能有一个场景运行（`scenario_lock` 互斥）
- 安全交底/开工会/收工会三个会议场景包含**语音录音转写**，发言经 Voice Gateway 直送 Runtime，不经过 Hermes
- 所有场景结果通过 `ReportPublisher` 上报至 WMCenter 安全管理系统
