
## `Settings.__init__()` 功能解析

这个函数是 FRD 项目的**全局配置中心**，它定义了一个 `Settings` 类，在实例化时从环境变量读取所有运行参数，并为每个参数提供合理的默认值。整个配置按功能域分为 **9 大块**：

---

### 🎤 1. 语音 / TTS（第 3-9 行）

| 配置项 | 默认值 | 含义 |
|--------|--------|------|
| `browser_voice` | `False` | 是否从浏览器端采集麦克风（现场语音由 voice_gateway 负责） |
| `tts_output` | `"gateway"` | TTS 播报出口：`gateway`→现场音箱，`ui`→仅前端页面播报 |
| `tts_backend` | `"g1"` | TTS 引擎：`pyttsx3`→本机系统 TTS，`g1`→宇树机器人内置 TTS |
| `ui_tts_enabled` | `False` | 兼容旧字段，实际以 `tts_output` 为准 |

---

### 🖥️ 2. 展示层 UI（第 12-22 行）

| 配置项 | 默认值 | 含义 |
|--------|--------|------|
| `ui_backend` | `"screen_g1"` | 前端类型：`screen_g1`→宇树胸屏对话界面，`legacy`→旧版静态 HTML |
| `screen_g1_dir` | `D:\work_project\Screen_G1\dist` | Screen_G1 前端构建产物目录 |
| `screen_g1_session_id` | 继承 `FRD_LOCAL_SESSION_ID` | 胸屏 WebSocket 绑定的 Runtime 会话 ID |
| `screen_g1_dialog_id` | `"frd_main"` | 推送到前端的对话 ID，用于区分不同对话流 |

### 🧪 3. 无硬件测试 / Mock（第 25-34 行）

| 配置项 | 默认值 | 含义 |
|--------|--------|------|
| `hardware_mock` | `False` | 是否开启 Mock 模式（不打开真实摄像头，返回假画面） |
| `face_recognition_bypass` | 跟随 `hardware_mock` | 是否跳过人脸识别，直接返回目标 ID |
| `mock_lobby_person_id` | `"2200000100000703"` | Mock 模式下的模拟人员 ID（周易） |
| `mock_lobby_person_name` | `"周易"` | 模拟人员的显示名 |

> **设计亮点**：`face_recognition_bypass` 默认跟随 `hardware_mock`，开启 Mock 后自动跳过识别，无需单独配置两个开关。

### 🚪 4. 大厅值守 / 人脸识别（第 37-57 行）

| 配置项 | 默认值 | 含义 |
|--------|--------|------|
| `lobby_watch_enabled` | `True` | 是否启用大厅轮询（摄像头持续检测人脸） |
| `lobby_poll_interval_sec` | `2.0` | 轮询间隔（秒） |
| `lobby_absent_sec` | `15` | 人员离开判定：连续未检测到时长的阈值 |
| `lobby_confirm_scans` | `2` | 身份确认所需连续命中次数 |
| `lobby_greet_min_interval_sec` | `10` | 同一人两次迎宾的最小间隔 |
| `lobby_greet_cooldown_sec` | `300` | 同一人迎宾冷却时间（5 分钟） |
| `lobby_faces_ttl_sec` | `4.0` | 人脸检测结果缓存有效期 |
| `face_match_threshold` | `0.60` | 人脸匹配相似度阈值（低于此值视为未识别） |
| `face_match_margin` | `0.08` | 第一名与第二名相似度差值下限（防误认） |
| `lobby_identity_lock_scans` | `2` | 锁定身份所需连续一致扫描次数 |
| `lobby_identity_switch_scans` | `3` | 切换已锁定身份所需连续新身份扫描次数 |

> **设计亮点**：相似度阈值 + 差值 margin 双重校验，以及身份锁定/切换的滞后机制，都在这里调参，无需改代码。

### 🧩 总结：这个 `__init__` 的设计精髓

1. **环境变量驱动**：每个配置项都通过 `_env()` / `_env_bool()` / `_env_int()` / `_env_float()` 从环境变量读取，优先级高于代码默认值。这意味着**部署时无需改代码，只需改 `.env` 文件或系统环境变量**。

2. **级联默认值**：部分配置的默认值依赖其他配置项，如 `face_recognition_bypass` 默认跟随 `hardware_mock`，`screen_g1_session_id` 回退到 `FRD_LOCAL_SESSION_ID`，形成智能的级联默认。

3. **关注点分离**：9 大功能域清晰分组，每个域内参数紧密相关，便于理解和维护。

4. **跨平台适配**：通过 `asr_backend`（funasr/vosk/g1）、`tts_backend`（pyttsx3/g1）、`camera_backend`（realsense/opencv/hikvision）等开关，同一套代码可以在 Windows 开发机、G1 机器人、不同硬件配置之间无缝切换。
