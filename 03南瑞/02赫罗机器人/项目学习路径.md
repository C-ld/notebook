## 📚 FRD 项目学习路径与顺序

### 🏷️ 项目概览

**FRD（Face Recognition Device）** 是一个**具身智能体应用终端**，运行在宇树 G1 人形机器人上，核心功能是**工作票安全管理**——通过人脸识别 + 语音交互执行安全交底、开工会、收工会、人员进出场等场景。系统由三个独立服务组成，采用**多会话架构**，支持多台机器人同时运行。

### 🟢 第二阶段：人脸识别服务（最底层能力）

这是整个系统的"眼睛"，独立运行，不依赖其他服务。

| 顺序 | 文件 | 核心内容 |
|------|------|----------|
| 5 | [recognition/core/face_module.py](file:///d:/workspace/python/FRD/recognition/core/face_module.py) | **核心引擎**：InsightFace 模型加载、人脸库构建、特征比对 |
| 6 | [recognition/core/paths.py](file:///d:/workspace/python/FRD/recognition/core/paths.py) | 数据路径管理（编码/图片/模型文件） |
| 7 | [recognition/repository/recognition_repository.py](file:///d:/workspace/python/FRD/recognition/repository/recognition_repository.py) | 人脸识别仓库层（封装底层调用，提供高层接口） |
| 8 | [recognition/server/face_server.py](file:///d:/workspace/python/FRD/recognition/server/face_server.py) | **Flask HTTP 服务**：串行推理队列、REST API |
| 9 | [recognition/service/recognition_adapters.py](file:///d:/workspace/python/FRD/recognition/service/recognition_adapters.py) | 适配器层：为 Runtime 提供场景化人脸识别封装 |

**关键设计思想：**
- `face_module.py` 使用 **串行推理队列** 避免多线程争用 InsightFace session
- 人脸库通过 `.npy` / `.pic` 编码文件管理，支持增量构建
- 识别服务与业务逻辑**完全解耦**，通过 HTTP API 通信

### 🟡 第三阶段：Runtime 业务核心（业务逻辑平台）

这是整个系统的"大脑"，包含多会话管理、场景引擎、MCP 协议。

| 顺序 | 文件 | 核心内容 |
|------|------|----------|
| 10 | [runtime/bootstrap.py](file:///d:/workspace/python/FRD/runtime/bootstrap.py) | **RuntimeContext**：依赖注入容器，组装所有组件 |
| 11 | [session/model/session_state.py](file:///d:/workspace/python/FRD/session/model/session_state.py) | 会话状态模型（状态机） |
| 12 | [session/model/session_context.py](file:///d:/workspace/python/FRD/session/model/session_context.py) | 会话上下文（dataclass） |
| 13 | [session/service/session_service.py](file:///d:/workspace/python/FRD/session/service/session_service.py) | 会话管理服务（创建/销毁/绑定） |
| 14 | [runtime/service/session_runtime.py](file:///d:/workspace/python/FRD/runtime/service/session_runtime.py) | **核心**：单会话场景执行引擎 |
| 15 | [config/scenarios.py](file:///d:/workspace/python/FRD/config/scenarios.py) | **所有场景定义**：安全交底/开工会/收工会/人员进出 |

**关键设计思想：**
- **多会话架构**：一台 Runtime 可以同时管理多个独立会话（每个机器人一个 session）
- **场景引擎**：`ScenarioRunner` → `RecognitionExecutor` → `ScenarioEngine` 三层执行模型
- 场景通过 `ScenarioConfig` 声明式定义，支持前置条件检查、参与者规则、识别类型等

---

### 🔵 第四阶段：语音网关（人机交互入口）

系统的"嘴巴和耳朵"，负责 ASR 语音识别 → TTS 语音合成 → Hermes Agent 对话。

| 顺序 | 文件 | 核心内容 |
|------|------|----------|
| 16 | [voice_gateway.py](file:///d:/workspace/python/FRD/voice_gateway.py) | 语音网关入口，连接 Runtime + Hermes |
| 17 | `voice/service/voice_gateway_bridge.py` | 语音桥接服务（核心事件循环） |
| 18 | `voice/repository/voice_factory.py` | 语音 IO 工厂（根据平台创建不同实现） |
| 19 | `runtime/service/voice_intent_handler.py` | 语音意图处理（将语音指令映射到场景动作） |

---

### 🟣 第五阶段：MCP 协议与 Agent 集成（智能体能力）

系统通过 MCP（Model Context Protocol）暴露工具给外部 AI Agent（Hermes）。

| 顺序 | 文件 | 核心内容 |
|------|------|----------|
| 20 | [agent/mcp/inprocess_mcp.py](file:///d:/workspace/python/FRD/agent/mcp/inprocess_mcp.py) | **MCP Server**：进程内 SSE 服务，暴露 8 个工具 |
| 21 | [agent/mcp/runtime_tools.py](file:///d:/workspace/python/FRD/agent/mcp/runtime_tools.py) | 工具实现：创建会话/运行场景/查询状态等 |
| 22 | [agent/mcp/mcp_compat.py](file:///d:/workspace/python/FRD/agent/mcp/mcp_compat.py) | MCP 兼容层 |
| 23 | [hermes-skills/](file:///d:/workspace/python/FRD/hermes-skills) | Hermes 技能定义（SKILL.md），每个场景一个技能 |

**关键设计思想：**
- **共享 MCP**：单 Hermes 多网关，通过 `hermes_session_id` 路由到正确的 Runtime 会话
- 工具设计遵循"异步启动 + 立即返回"模式，避免 MCP 调用阻塞

### 💡 学习建议

1. **先跑起来**：在 Windows 上以 mock 模式启动（设置 `FRD_HARDWARE_MOCK=true`），不需要真实摄像头和 G1 机器人
2. **按服务拆分理解**：`face_server.py`（端口 5000）→ `runtime_server.py`（端口 28000）→ `voice_gateway.py`，按依赖顺序逐个启动
3. **从场景入手**：[scenarios.py](file:///d:/workspace/python/FRD/config/scenarios.py) 是理解业务逻辑的最佳入口，先看懂一个简单场景（如 `workLeaderSignIn`），再扩展到复杂场景
4. **关注设计模式**：依赖注入（`RuntimeContext`）、适配器模式（`recognition_adapters`）、声明式场景配置、多会话架构都是值得学习的工程实践
