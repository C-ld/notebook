# FRD 前端状态机设计

  

## 概述

  

将前端重构为以场景为单位的视图驱动架构。每个场景拥有独立的状态机，状态决定当前页面展示的内容。每个状态的页面只关注该状态相关的信息，不再维护全局对话历史列表。

  

---

  

## View 组件定义

  

| View ID | 名称 | 说明 |

|---------|------|------|

| `ticket_card` | 工作票信息卡 | 工作票编号、工作负责人、成员列表、工作内容摘要 |

| `identity_preview` | 身份预览区 | 摄像头实时画面 + 人脸框 + 识别状态文字 |

| `person_info` | 人员信息条 | 当前识别/签到人员的姓名、角色（负责人/成员）、头像 |

| `pending_prompt` | 待签到提示 | "XXX，您有待执行工作票「XXX」，是否进行签到？" |

| `scenario_title` | 场景标题栏 | 当前场景名称 + 阶段描述 |

| `participant_grid` | 参与人员网格 | 应到人员头像 + 姓名 + 识别状态（已识别/未识别/识别中） |

| `recording_panel` | 录音面板 | 录音动画 + 已录制时长 + "说「结束」完成录音" + 实时转写文字 |

| `result_card` | 结果卡片 | 成功/失败图标 + 场景名 + 人员名单 + 时间戳 |

| `lobby_greeting` | 迎宾问候 | 欢迎语 + 人员姓名 |

| `gateway_indicator` | 网关指示器 | 语音网关在线/离线小圆点（全局常驻） |

## 全局状态机

  

```

                    ┌──────────┐

   展示端连接  ──→  │  IDLE    │  ←── 展示端断开

                    └────┬─────┘

                         │ 有展示端连接

                         ▼

              ┌────────────────────┐

              │  LOBBY_SCANNING    │

              │                    │

              │  LobbyIdle         │  无人

              │    ↓               │

              │  PersonDetected    │  检测到人脸

              │    ↓               │

              │  IdentityConfirmed │  身份匹配成功

              │    ↓               │

              │  AwaitingSignIn    │  有待签到工作票

              └────────┬───────────┘

                       │ 用户说签到 / 启动场景

                       ▼

              ┌────────────────────┐

              │  SCENARIO_RUNNING  │

              │  (具体场景子状态机)  │

              └────────┬───────────┘

                       │ 场景结束

                       ▼

                   回到 IDLE

```

  

### IDLE（空闲）

  

页面空白，仅显示 `gateway_indicator`。等待展示端连接。

  

### LOBBY_SCANNING（迎宾扫描）

  

| 子状态 | 页面内容 |

|--------|----------|

| **LobbyIdle** | 居中文字"等待人员入场…" |

| **PersonDetected** | `identity_preview`（实时画面 + 人脸框 + "识别中…"） |

| **IdentityConfirmed** | `identity_preview`（锁定画面 + 姓名） + `lobby_greeting`（"XXX，您好"） |

| **AwaitingSignIn** | `identity_preview`（锁定 + "待签到 · XXX工作票"） + `pending_prompt`（"您有待执行工作票，是否签到？"） |

## 场景一：工作负责人签到 (workLeaderSignIn)

  

### 状态机

  

```

PREREQUISITES ──→ WAITING ──→ RECOGNIZING ──→ COMPLETED

    │                              │               │

    └──────────→ FAILED  ←─────────┘               │

                                                   │

                                            FAILED（重试耗尽）

```

  

### PREREQUISITES — 前置检查

  

页面展示当前工作票的核心信息，让用户确认场景已启动。

  

| View | 内容 |

|------|------|

| `ticket_card` | 工作票编号、工作负责人姓名、工作内容摘要 |

| `scenario_title` | "工作负责人签到" / "检查中…" |

  

### WAITING — 等待就位

  

引导工作负责人站到摄像头前。

  

| View | 内容 |

|------|------|

| `ticket_card` | 同上 |

| `scenario_title` | "工作负责人签到" / "请正对摄像头" |

| `identity_preview` | 实时画面 |

| `person_info` | 待签到：XXX（工作负责人姓名） |

  

### RECOGNIZING — 识别中

  

| View | 内容 |

|------|------|

| `ticket_card` | 同上 |

| `scenario_title` | "工作负责人签到" / "第 N 次识别…" |

| `identity_preview` | 实时画面 + 人脸框 |

| `person_info` | 待签到：XXX（工作负责人姓名），状态"识别中…" |

  

失败回 WAITING 时：`identity_preview` 下方短暂显示红色文字"识别失败，请重新正对摄像头"。

  

### COMPLETED — 签到成功

  

| View | 内容 |

|------|------|

| `result_card` | ✅ 签到成功 / 工作负责人：XXX / 工作票编号：XXXXXX / 时间 |

| `ticket_card` | 同上（保留上下文） |

  

### FAILED — 签到失败

  

| View | 内容 |

|------|------|

| `result_card` | ❌ 签到失败 / 原因：重试次数过多 / 工作负责人：XXX |

| `ticket_card` | 同上 |

## 场景二：安全交底 (AQJD)

  

### 状态机

  

```

PREREQUISITES → WAITING → RECOGNIZING → PARTICIPANTS_CONFIRMED → LEADER_SPEECH → COMPLETED

    │               │           │                  │

    └──→ FAILED  ←──┘           └──→ FAILED        │

                                                    │

                                            录音完成

```

  

### PREREQUISITES — 前置检查

  

| View | 内容 |

|------|------|

| `ticket_card` | 工作票信息 |

| `scenario_title` | "安全交底" / "检查前置条件…" |

  

### WAITING — 等待人员就位

  

| View | 内容 |

|------|------|

| `ticket_card` | 工作票信息 |

| `scenario_title` | "安全交底" / "请所有交底人员站到摄像头前方" |

| `identity_preview` | 实时画面 |

| `participant_grid` | 全员灰色（未识别），列出所有交底人员姓名 |

  

### RECOGNIZING — 人员识别中

  

| View | 内容 |

|------|------|

| `ticket_card` | 工作票信息 |

| `scenario_title` | "安全交底" / "人员识别中…（M/N）" |

| `identity_preview` | 实时画面 + 人脸框 + 当前匹配姓名 |

| `participant_grid` | 已识别绿色高亮 + 打勾，未识别灰色 + 待识别标记 |

  

每识别到一人，`participant_grid` 中对应卡片翻转/高亮。

  

### PARTICIPANTS_CONFIRMED — 人员确认完成

  

| View | 内容 |

|------|------|

| `ticket_card` | 工作票信息 |

| `scenario_title` | "安全交底" / "人员确认完成" |

| `participant_grid` | 全部绿色高亮，显示"已识别：N人"，底部提示"即将开始交底发言…" |

  

### LEADER_SPEECH — 交底发言录音

  

| View | 内容 |

|------|------|

| `ticket_card` | 工作票信息 |

| `scenario_title` | "安全交底" / "交底发言中…" |

| `participant_grid` | 折叠为摘要行（已识别 N 人：XXX、YYY…） |

| `recording_panel` | 录音动画 + 计时 + 实时转写文字 + "说「结束」完成发言" |

  

### COMPLETED — 完成

  

| View | 内容 |

|------|------|

| `result_card` | ✅ 安全交底完成 / 交底人员：N人 / 发言摘要 / 时间 |

| `ticket_card` | 同上 |

  

### FAILED — 失败

  

| View | 内容 |

|------|------|

| `result_card` | ❌ 安全交底失败 / 原因：未识别到任何交底人员 |

| `ticket_card` | 同上 |

## 场景五/六：人员进场 (workerEnter) / 人员出场 (workerExit)

  

### 状态机

  

```

PREREQUISITES → WAITING → RECOGNIZING → BATCH_RECOGNIZED → CONTINUE_OR_STOP → COMPLETED

    │               │           │              │                    │

    └──→ FAILED  ←──┘           │              └──→ 用户说"继续"回 RECOGNIZING

                                │

                          全部识别完成 → COMPLETED

```

  

### PREREQUISITES — 前置检查

  

| View | 内容 |

|------|------|

| `ticket_card` | 工作票信息 |

| `scenario_title` | "人员进场" 或 "人员出场" / "检查前置条件…" |

  

### WAITING — 等待人员就位

  

| View | 内容 |

|------|------|

| `ticket_card` | 工作票信息 |

| `scenario_title` | "人员进场" / "请所有进场人员站到摄像头前方" |

| `identity_preview` | 实时画面 |

| `participant_grid` | 待进场/出场人员列表（全员灰色） |

  

### RECOGNIZING — 识别中

  

| View | 内容 |

|------|------|

| `ticket_card` | 工作票信息 |

| `scenario_title` | "人员进场" / "识别中…（M/N）" |

| `identity_preview` | 实时画面 + 人脸框 |

| `participant_grid` | 已识别高亮，未识别灰色 |

  

### BATCH_RECOGNIZED — 本批识别完成

  

| View | 内容 |

|------|------|

| `ticket_card` | 工作票信息 |

| `scenario_title` | "人员进场" / "本批识别完成" |

| `participant_grid` | 已识别高亮（本批标记"新进场"），未识别灰色 |

  

### CONTINUE_OR_STOP — 等待指令

  

| View | 内容 |

|------|------|

| `ticket_card` | 工作票信息 |

| `scenario_title` | "人员进场" / "仍有 N 人未进场" |

| `participant_grid` | 已识别 vs 未识别对比 |

| 底部提示 | 语音提示文字："是否继续？说「继续」或「结束」" |

  

### COMPLETED — 完成

  

| View | 内容 |

|------|------|

| `result_card` | ✅ 人员进场完成 / 进场：N人（姓名列表）/ 时间 |

| `ticket_card` | 同上 |

  

### FAILED — 失败

  

| View | 内容 |

|------|------|

| `result_card` | ❌ 人员进场失败 / 原因：未识别到任何进场人员 |

| `ticket_card` | 同上 |

## 后端 → 前端协议

  

后端在场景状态变更时推送统一消息，前端本地驱动状态机：

  

```jsonc

{

  "type": "state_change",

  "data": {

    "global": "SCENARIO",                // IDLE | LOBBY | SCENARIO

    "scenario": {

      "id": "AQJD",

      "name": "安全交底",

      "state": "RECOGNIZING",           // 当前子状态

      "progress": { "total": 5, "done": 2 }

    },

    "payload": {

      "ticket": {

        "id": "123456",

        "leader_name": "张三",

        "summary": "10kV线路检修",

        "members": [

          { "id": "001", "name": "李四", "role": "member", "avatar": "" },

          { "id": "002", "name": "王五", "role": "member", "avatar": "" }

        ]

      },

      "identity_preview": {

        "action": "show",                // show | update | hide

        "image_b64": "...",

        "persons": ["李四"],

        "status": "recognizing"

      },

      "participants": {

        "required": ["001", "002"],

        "recognized": ["001"]

      },

      "recording": null,                 // null=不启用

      "result": null                     // null=不启用

    }

  }

}

```

  

前端收到后：

1. 若 `global` 变更 → 切换顶层路由（进入/退出场景页）

2. 若 `scenario.state` 变更 → 本地状态机驱动 View 显隐

3. 数据直接对应到 View props，无需前端拼装
