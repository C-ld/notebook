## 如何培养想 idea 的能力
https://pengsida.notion.site/idea-da6ce171c13846b7a7ffaa7473ffa6ea

1、规划科研方向的 general goal，制定达到这个 general goal 的 roadmap。
	一般而言，general goal 容易定义，但制定roadmap需要对领域有深刻的理解。
	可以通过构建 literature tree（进行 literature review，构建 novelty tree 和 challenge-insight tree）来建立起对该领域的认知。
2、根据 novelty-tree 列出的 roadmap，选择有研究空间的 task，调研这个 task 有没有重要的technical challenge。**选题是对一个 research project 影响最大的一步，而不是后面的想方法。**
	怎么找到重要的科研问题： 去思考这个任务长远的目标，一个最终形态是怎样的。 为什么当前工作只在这些数据上做，而不在其他数据上做。应该尝试更多的 general cases 的数据。 追求发现新的 failure cases，从新的 failure cases 入手改进原有的技术。（1. 在新的 task setting或者新的数据上容易发现新的 failure cases。 2. 在新的数据上探索方法的可能性，让大家看到新的实验结论，这是很大的贡献。）
3、从技术层面上分析现在的 pipelines 在某个 task 上不 work 的原因，在 pipeline module 层面思考可能的原因，然后在 pipeline 层面或 high-level idea 层面思考可能的原因。
4、上升到 high-level idea、pipeline、modules 层面进行创新，想出一些技术贡献。具体做法看这个文档：[https://www.notion.so/pengsida/pipeline-997f611cd2e24ef1a62210ff099948e2](https://www.notion.so/pengsida/pipeline-997f611cd2e24ef1a62210ff099948e2)
5、在一些数据上验证这个技术贡献，调效果。


### 如何改进一篇论文 / 一个pipeline

如何从根本上提升改进pipeline的能力：多看论文；多思考；多做实验；多与人讨论；多积累已有的技术、insights和存在的问题。

从博士生培养的角度来看为什么要改进pipeline：博士生要努力成为一个很技术的人，对现有以及新兴的技术有很好的学习能力、思考能力、剖析能力，可以很好地在一个任务上深入地改进这个技术以提升该技术在此任务上的性能。如果只是简单地将一个技术用在某个任务上，这样的事情，我相信大多数本科生也能做。 我猜测reviewers总是希望论文有技术贡献，大概也是因为希望看到论文有更多的技术创新和剖析，而不只是看到新的task、story或applications。如果一篇论文只是讲story而没提新技术，这样子实际上对领域中技术的发展没帮助。


1. 思考现在的 pipeline 存在什么问题。怎么找到 pipeline 的“问题”：
    1. 首先思考我们的target task有哪些 ***指标***，比如在各种数据上效果都要很好、训练速度快、推理速度快、易用性高。
	    
    2. 然后通过看论文、思考、做实验、与人讨论等方式，发现当前的 pipeline满足不了哪个指标。**一般是在某某数据上效果不好、当实验条件变宽松时效果变差、训练速度不够快、推理速度不够快、易用性不够高。**
2. 针对找到的“问题”，思考为什么这个pipeline会有这个问题，推测众多的深层次的技术原因。怎么推测技术原因：
    1. 首先从已有的论文蒸馏知识。**寻找有没有解决相似“问题”的论文，看看这些论文里有没有分析导致“问题”的技术原因**（寻找相关的论文要发散一些，从同一个方向的论文找到不同方向的论文。主要靠自己找论文，以及问senior advisor、学长学姐有没有看过相关的论文。**论文Introduction的前两三段一般会讨论之前论文的问题及其技术原因**）。
        
        相关文档：[如何有效地读论文](https://www.notion.so/d192db870bc64436ae4a4a590b36772a?pvs=21)、[怎么找论文](https://www.notion.so/c278dab7e4764d61a92c1fd1ef3135b1?pvs=21)
        
    2. 然后总结从论文获得的知识。总结这些论文的分析，形成自己的一套思考。
        
        相关文档：[怎么总结论文](https://www.notion.so/f8b36e484b344a2893a94e4608b72ec2?pvs=21)
        
    3. 然后从有经验的人身上蒸馏知识。找有经验的人讨论，分享自己对这个问题的思考，通过分享自己的观点来加深自己的思考以及启发自己的更多思考，并且期望对方有一些不一样的思考，从而积累对“问题”的认识，积累导致“问题”的技术原因（**我们要养成看到有启发性的论文找人讨论的习惯，复述一遍论文也行，说一些对论文的想法也行**）。
        
    4. 然后从实验获得知识。通过实验验证这些技术原因，得到更多的实验观察。
3. 根据众多的深层次的技术原因，改进当前的 pipeline。有两种改进 pipeline 的情况：
    1. 第一种情况，从 pipeline level 做改进，提出新的 pipeline、新的 framework。怎么做出这样的改进：
        1. 首先从已有的论文蒸馏知识。看看已有的论文都有哪些 pipelines ，为什么这些 pipeline 能解决相应的问题，看看已有论文对现有 pipelines 的分析。
        2. 然后总结从论文获得的知识。分析各种 pipelines 为什么要这么设计，有什么好处和坏处。
        3. 然后从有经验的人身上蒸馏知识。找有经验的人讨论，分享自己对已有 pipelines 的思考，通过分享自己的观点来加深自己的思考以及启发自己的更多思考，并且期望对方有一些不一样的思考，从而积累对 pipelines 的认识（**我们要养成看到有启发性的论文找人讨论的习惯，复述一遍论文也行，说一些对论文的想法也行**）。
        4. 然后从实验获得知识。基于总结的 pipelines 及其优劣，改进一个pipeline，并做实验看看，得到更多的实验观察。
    2. 第二种情况，从 module level 做改进，改进 pipeline 中的 modules。
        1. 首先从已有的论文蒸馏知识。看看当前 pipeline 的 modules 在文献中都有哪些变种，为什么这些 modules 能解决相应的问题，看看已有论文对现有 modules 的分析。
        2. 然后总结从论文获得的知识。分析各种 modules 为什么要这么设计，有什么好处和坏处。
        3. 然后从有经验的人身上蒸馏知识。找有经验的人讨论，分享自己对已有 modules 的思考，通过分享自己的观点来加深自己的思考以及启发自己的更多思考，并且期望对方有一些不一样的思考，从而积累对 modules 的认识。
        4. 然后从实验获得知识。基于总结的 modules 及其优劣，改进一个 module，并做实验看看，得到更多的实验观察。

# 科研能力

- 阅读大量论文的能力、进行literature review的能力、构建literature tree的能力、追踪积累最新论文/技术的能力
- 想Idea的能力（Goal-driven research的能力、search的能力、提出新的technique的能力）
- 代码能力、实验能力、分析实验不work的原因的能力
- 写作能力、展示能力、把一篇论文做得漂亮的能力、做demo的能力
- 和导师、同学交流讨论的能力
- 在各种情况下保持平和的心态，追求“空白的心灵”

# 科研 project 流程

1. 想重要的 task
2. 想需要解决的 technical challenge/failure case
3. 想解决问题的解法
4. 梳理解法的逻辑
5. 判断解法的正确性和新颖性
6. 设计简单实验快速验证解法的正确性
7. 改进解法
8. 畅想更多的候选解法
9. 做实验把解法调 work
10. 想下一步做什么
11. 梳理清楚下一步做什么
12. 根据论文的截止日期设置自己论文重要的几个截止时间（对比实验、ablation study、introduction写作、method写作、abstract写作、experiment写作、related work写作）
13. 写论文
14. Review论文 (列出缺少的实验和存在的写作问题)
15. 改论文
