## [监听事件](https://v2.cn.vuejs.org/v2/guide/events.html#%E7%9B%91%E5%90%AC%E4%BA%8B%E4%BB%B6 "监听事件")

[观看本节视频讲解](https://learning.dcloud.io/#/?vid=10 "Vue.js 教程 - 事件绑定")

可以用 `v-on` 指令监听 DOM 事件，并在触发时运行一些 JavaScript 代码。

示例：

```html
<div id="example-1">  
	<button v-on:click="counter += 1">Add 1</button>  
	<p>The button above has been clicked {{ counter }} times.</p>  
</div>
```

```js
var example1 = new Vue({  
	el: '#example-1',  
	data: {  
		counter: 0  
	}  
})
```


## [事件处理方法](https://v2.cn.vuejs.org/v2/guide/events.html#%E4%BA%8B%E4%BB%B6%E5%A4%84%E7%90%86%E6%96%B9%E6%B3%95 "事件处理方法")

然而许多事件处理逻辑会更为复杂，所以直接把 JavaScript 代码写在 `v-on` 指令中是不可行的。因此 `v-on` 还可以接收一个需要调用的方法名称。

```html
<div id="example-2">  
	<!-- `greet` 是在下面定义的方法名 -->  
	<button v-on:click="greet">Greet</button>  
</div>
```

```js
var example2 = new Vue({  
	el: '#example-2',  
	data: {  
		name: 'Vue.js'  
	},  
	// 在 `methods` 对象中定义方法  
	methods: {  
		greet: function (event) {  
			// `this` 在方法里指向当前 Vue 实例  
			alert('Hello ' + this.name + '!')  
			// `event` 是原生 DOM 事件  
			if (event) {  
				alert(event.target.tagName)  
			}  
		}  
	}  
})

// 也可以用 JavaScript 直接调用方法  
example2.greet() // => 'Hello Vue.js!'
```

## [内联处理器中的方法](https://v2.cn.vuejs.org/v2/guide/events.html#%E5%86%85%E8%81%94%E5%A4%84%E7%90%86%E5%99%A8%E4%B8%AD%E7%9A%84%E6%96%B9%E6%B3%95 "内联处理器中的方法")

除了直接绑定到一个方法，也可以在内联 JavaScript 语句中调用方法：

> ps：就是可以传参

```html
<div id="example-3">  
	<button v-on:click="say('hi')">Say hi</button>  
	<button v-on:click="say('what')">Say what</button>  
</div>
```

```js
new Vue({  
	el: '#example-3',  
	methods: {  
		say: function (message) {  
			alert(message)  
		}  
	}  
})
```

有时也需要在内联语句处理器中访问原始的 DOM 事件。可以用特殊变量 `$event` 把它传入方法：

```html
<button v-on:click="warn('Form cannot be submitted yet.', $event)">  
	Submit  
</button>
```

```js
// ...  
methods: {  
	warn: function (message, event) {  
	// 现在我们可以访问原生事件对象  
	if (event) {  
		event.preventDefault()  
	}  
	alert(message)  
	}  
}
```


## [事件修饰符](https://v2.cn.vuejs.org/v2/guide/events.html#%E4%BA%8B%E4%BB%B6%E4%BF%AE%E9%A5%B0%E7%AC%A6 "事件修饰符")

在事件处理程序中调用 `event.preventDefault()` 或 `event.stopPropagation()` 是非常常见的需求。尽管我们可以在方法中轻松实现这点，但更好的方式是：方法只有纯粹的数据逻辑，而不是去处理 DOM 事件细节。

为了解决这个问题，Vue.js 为 `v-on` 提供了**事件修饰符**。之前提过，修饰符是由点开头的指令后缀来表示的。

- `.stop`
- `.prevent`
- `.capture`
- `.self`
- `.once` 2.1.4 新增，只触发第一次，后续点击无效
- `.passive` 2.3.0 新增，用于 addEventListener

```html
<!-- 阻止单击事件继续传播 -->  
<a v-on:click.stop="doThis"></a>  
  
<!-- 提交事件不再重载页面 -->  
<form v-on:submit.prevent="onSubmit"></form>  
  
<!-- 修饰符可以串联 -->  
<a v-on:click.stop.prevent="doThat"></a>  
  
<!-- 只有修饰符 -->  
<form v-on:submit.prevent></form>  
  
<!-- 添加事件监听器时使用事件捕获模式 -->  
<!-- 即内部元素触发的事件先在此处理，然后才交由内部元素进行处理 -->  
<div v-on:click.capture="doThis">...</div>  
  
<!-- 只当在 event.target 是当前元素自身时触发处理函数 -->  
<!-- 即事件不是从内部元素触发的 -->  
<div v-on:click.self="doThat">...</div>
```




## Aped 01 冒泡传播 & .stop 使用场景
### 为什么事件会"继续传播"

这是因为浏览器 DOM 的事件模型中有一种机制叫**事件冒泡（Event Bubbling）**。当一个元素上的事件被触发时，浏览器会经历三个阶段：

1. **捕获阶段**：事件从 `document` 向下传播到目标元素
2. **目标阶段**：事件到达实际触发它的元素
3. **冒泡阶段**：事件从目标元素开始，逐级向上传播回 `document`

默认情况下，`v-on` 绑定的事件处理器是在**冒泡阶段**执行的。所以当你点击一个嵌套的子元素时，点击事件会先被子元素捕获处理，然后沿着 DOM 树向上冒泡，依次触发父元素、祖父元素……上绑定的同类型事件处理器。

比如说你有一个下拉菜单：

```html
<div v-on:click="closeMenu">
  <button v-on:click="showDropdown">打开菜单</button>
</div>
```

点击按钮时，事件首先触发按钮上的 `showDropdown`，然后冒泡到外层 `div`，触发 `closeMenu`。结果菜单刚打开就被关闭了。

### `.stop` 的使用场景

`.stop` 就是用来解决这类父子元素事件冲突的。最常见的场景包括：

**卡片/列表项中的操作按钮**

```html
<div v-on:click="goToDetail">
  <h3>{{ title }}</h3>
  <button v-on:click.stop="deleteItem">删除</button>
</div>
```

点击"删除"按钮时，`.stop` 阻止事件冒泡到外层卡片，避免同时触发 `goToDetail` 跳转到详情页。

**模态框/弹窗的遮罩层**

```html
<div class="modal-overlay" v-on:click="closeModal">
  <div class="modal-content" v-on:click.stop>
    <!-- 弹窗内容 -->
  </div>
</div>
```

点击遮罩层关闭弹窗，但点击弹窗内部内容时，`.stop` 阻止事件冒泡到遮罩层，避免点击弹窗内容也不小心关掉弹窗。

**嵌套的交互组件**

比如一个表格行可以点击查看详情，但行内的某个操作按钮（编辑、删除、复制等）需要独立响应，不被行的点击事件干扰。

简单来说，**`.stop` 解决的是"子元素触发的事件意外触发父元素事件"的问题**，这在嵌套 UI 结构中是极其常见的需求。

 
## Aped 02 什么是浏览器的默认行为

浏览器的默认行为，指的是浏览器在用户触发某些事件时会自动执行的内置动作。这些行为是浏览器原生就有的，不需要开发者编写任何代码。以下是前端开发中最常见的几种默认行为：

### 1. 表单提交 —— 页面重载 / 跳转

当用户点击 `<form>` 内的提交按钮（`<button type="submit">` 或 `<input type="submit">`）或在表单中按回车时，浏览器会自动收集表单数据，按 `action` 属性指定的 URL 发起请求并**刷新页面**。如果没写 `action`，则默认提交到当前页面地址，导致页面重新加载。

```html
<form action="/search" method="GET">
  <input name="q" />
  <button type="submit">搜索</button>
</form>
```

点击提交后，浏览器会导航到 `/search?q=xxx`。在 Vue 单页应用中，你通常希望用 Ajax 异步提交数据，不刷新页面，所以需要调用 `event.preventDefault()` 来阻止这个行为。

### 2. 链接点击 —— 页面跳转

点击 `<a href="...">` 时，浏览器会导航到 `href` 指定的地址。虽然这不一定是坏事，但在某些场景下你需要阻止它——比如用 Vue Router 做客户端路由时，希望用 JavaScript 控制跳转流程。

### 3. 右键点击 —— 弹出上下文菜单

鼠标右键点击页面时，浏览器会自动弹出右键菜单（"复制"、"粘贴"、"检查"等）。如果你要实现自定义右键菜单（比如在画布工具或富文本编辑器中），就需要阻止这个默认行为。

### 4. 拖拽文件到浏览器 —— 直接打开文件

如果把本地文件拖拽到浏览器窗口中，浏览器会默认直接在页面中打开该文件。这在实现文件上传的拖拽区域时是需要阻止的。

### 5. 键盘按键 —— 输入字符

在输入框中按下字符键时，浏览器会把字符插入输入框。如果你开发的是快捷键面板或自定义输入组件，可能需要在特定情况下阻止字符输入。

### 6. 鼠标滚轮 —— 页面滚动

滚动鼠标滚轮时，浏览器会滚动页面。在实现自定义滚动容器或无限滚动组件时，有时需要先阻止默认滚动行为，再通过 JavaScript 控制滚动逻辑。

### 在 Vue 中如何应对

Vue 的 `.prevent` 修饰符本质就是 `event.preventDefault()` 的简写：

```html
<!-- 阻止表单提交时的页面重载 -->
<form v-on:submit.prevent="onSubmit"></form>

<!-- 阻止链接跳转 -->
<a v-on:click.prevent="handleClick">点我</a>

<!-- 阻止右键菜单 -->
<div v-on:contextmenu.prevent="showCustomMenu">右键区域</div>
```

**总结：**.`prevent` 解决的是"浏览器自动做了你不想让它做的事"这类问题，特别是当你要用 JavaScript 接管这些原生交互逻辑时。


## Aped 03 默认行为和监听器，.passive的应用场景


`.passive` 的底层机制需要从浏览器的**事件处理流程**讲起。

### 核心问题：浏览器在等什么？

当一个事件（比如滚动或触摸）被触发时，浏览器在执行完 JavaScript 事件处理器之前，**不知道处理器是否调用了 `event.preventDefault()`**。

- 如果调用了，浏览器就必须**取消**默认行为（比如不滚动）
- 如果没调用，浏览器就应该**执行**默认行为（比如继续滚动）

问题是：浏览器必须等 JavaScript 执行完才能知道结果。这就造成了一个两难——如果 JavaScript 执行时间较长，滚动操作就会被延迟，用户会感知到"卡顿"（术语叫 **jank**）。

### 机理图示

```
没有 .passive 时（默认）：
  用户手指滑动 → 浏览器触发 touchmove 事件
                → 【等待 JS 执行完毕】
                → JS 没调 preventDefault() → 浏览器开始滚动       ← 有延迟

有 .passive 时：
  用户手指滑动 → 浏览器触发 touchmove 事件
                → 【立即开始滚动】（不等 JS）   ← 无延迟
                → JS 同时执行，但即使调了 preventDefault() 也无效
```

### `.passive` 做了什么

`{ passive: true }` 本质上是向浏览器作出一个**承诺**：这个事件处理器**不会调用 `preventDefault()`**。浏览器收到这个承诺后，就可以放心地在执行 JavaScript 的同时，立即启动默认行为（比如滚动），二者并行进行，互不阻塞。

用 `addEventListener` 的第三个参数更直观：

```js
// 默认行为——浏览器需要等待，怕你调 preventDefault
element.addEventListener('scroll', handler)

// 被动模式——浏览器直接执行默认行为，不等你
element.addEventListener('scroll', handler, { passive: true })
```

Vue 的 `.passive` 修饰符就是在底层绑定了 `{ passive: true }`。

### 为什么特别提升移动端性能

移动端浏览器会在用户触摸屏幕时就立即需要决定是否滚动。如果每次触摸都要先等 JavaScript 跑完，延迟会非常明显。`.passive` 消除了这个等待过程，让滚动响应几乎零延迟，所以文档中说"尤其能够提升移动端的性能"。

### 注意事项

文档中强调"不要把 `.passive` 和 `.prevent` 一起使用"，原因是二者逻辑矛盾：`.passive` 承诺不阻止默认行为，但 `.prevent` 偏要去阻止，结果是 `.prevent` 被忽略，浏览器还可能弹出警告。
